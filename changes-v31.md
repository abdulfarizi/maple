# M-ID v31 · new homepage, one header, bottom music player, Music I Like, Anime

- **Homepage redesign**: new hero ("One digital ID for every game handle, stream, and social."), lighting and glass, floating claim field with live availability light, theme picker that crossfades the example card, game ticker (Mobile Legends, Roblox, Free Fire, Minecraft, Valorant, Genshin Impact …), new bento, restyled Explore and sign-up. All IDs kept (#claim-form, #claim-slug, #claim-status, #ex-q, #ex-list, [data-sort], #auth-form …).
- **One global header**: the M-ID header now stays on star-layout cards too (their own in-card header is hidden inside the app). Desktop gets Home · Explore · Profile links and an Alerts bell; mobile keeps the menu. On a profile, a **View** button shows only the controls that owner switched on: theme (limited to the themes they picked), language (star cards), card sounds.
- **Bottom music player** replaces the header music button: mini-player above the dock, slides up to a full Now Playing sheet. Uses Spotify's official embed (iFrame API) only, with progress, play/pause and ±10 s. Optional lyrics from LRCLIB, highlighted and scrolled line by line when synced. Star cards without a Spotify link keep their theme music in the same player.
- **Music I Like** and **Anime** collections on every layout (star cards: new tabs in the card's swipe pager; basic cards: a sticky section bar). Managed in Studio → **Music & anime** (add Spotify links with automatic title/artwork, AniList search, status, rating, notes, reorder, live preview).
- Data is stored inside the existing profile record (same `profiles` row as everything else, whitelisted and cleaned in the bridge). **No database change, no SQL to run.**
- New endpoint `/api/spotify-meta` (Netlify function + Vercel function). Optional: set `SPOTIFY_CLIENT_ID` and `SPOTIFY_CLIENT_SECRET` as server environment variables to also get artist names and durations. Without them it uses Spotify oEmbed (title + artwork).
